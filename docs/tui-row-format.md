# TUI 行排版格式规范

对话流与面板里每一行都按本文的某一套格式排版。三套各守各的,**不要跨套借用写法**;
新增一种行先判断它属于哪一套,套内已有写法直接照抄。

## 通用工具套

适用:Read、Edit、Write、ls、find、grep、Subagent 等所有工具调用行、子代理组与清单、
任务卡头行——除 Bash 与思考块之外的一切"标签行"。

```text
[标记] 标签  详情  (统计)
```

- **标记**:调用行 `›`、展开态 `◆`/`◈`;标记后 1 个空格。
- **段间隔恒为两个空格**:标签与详情之间、详情与统计段之间都是 2 格,不出现 1 格衔接。
- **圆括号 = 统计段**,恒在行尾:耗时、行数、token 等计量进括号,段内多值用 ` · `
  (`(12 steps · 14.3s)`)。计数与状态词(`2/5`、`2 done`、`1 running`)是状态不是
  计量,裸文本不进括号。
- **统计段位置**:单行紧跟详情;清单类(多行同构)右对齐钉行尾形成一列——数字对齐
  比紧凑重要。
- 例:`› Read  a.ts (12 lines)`、`› Edit  a.ts (+2/-1)`、
  `◈ Subagents  2 done (2m16s)`、`● Subagent1  熟悉后端  (14.3s)`、`› Tasks  2/5`。

## Bash 套

适用:bash 工具行。形态与通用套相同,但折叠行 metric 恒为本条命令的耗时
(`› Bash  npm test (1.2s)`),失败行显示失败原因(`× Bash  exit 1 (0.0s)`)。
不与 resultMetric 的各行指标混用,是刻意保留的差异:命令的价值在"跑了多久"。

## Thought 套

适用:思考区块标题。句子式而非标签式,耗时**不进括号**:

```text
✻ Thinking… 0.8s
✻ Thought for 1.2s
```

它是唯一以完整句子呈现的行,保留叙述语气;除此之外的耗时一律走括号。

## 豁免行

页脚信息行(分组信息带:`|` 分组、`·` 组内)与运行时状态行不是标签行,
各有自己的格式,不受本规范约束。
