以根目录 `AGENTS.md`（规范，冲突时以其为准）与 `config.toml`（配置面权威）为基准；`reference/pi` 只取设计思路，不搬代码、不搬命名，注释中不出现任何引用其他项目的字样。

## 二、内置还是插件

**必须内置**（安全边界 / 核心语义 / 宿主必须掌握全集，任一命中）：

| 组件 | 命中 | 依据 |
|---|---|---|
| `agent/`（回合驱动 + 事件协议） | 核心语义 | 换掉就不是同一个产品 |
| `llm/`（接缝 + 适配器 + 凭证解析） | 安全边界 + 核心语义 | 唯一持有凭证、唯一出站；内置后插件在结构上无法拦截或外传模型流量 |
| `tools/`（契约 + 注册表 + 校验 + 调用管线） | 核心语义 + 安全边界 + 掌握全集 | 管线 `校验→权限→沙箱→执行→落盘` 就是安全路径；权限要对工具全集做判定 |
| 核心工具 `read` / `write` / `edit` / `bash` | 核心语义 + 安全边界 | `read`/`write`/`edit` 是"能改代码"的最小闭环，`edit` 的语义（对原文件匹配、唯一且不重叠、BOM 与行尾保留）本身就是产品承诺；`bash` 是任意代码执行 |
| `session/`（SessionPort + 条目 schema） | 核心语义 + 掌握全集 | 压缩、导出、界面都要枚举条目类型；schema 一乱历史不可重放 |
| `sandbox/`（模式判定 + fail-closed） | 安全边界 | 「现在到底有没有隔离」是安全结论 |
| `permission/` | 安全边界 | 策略链与默认拒绝不可外包 |
| `workspace/`（路径边界 + 信任） | 安全边界 | 插件在信任决议**之后**才加载 |
| `config/` | 掌握全集 + 安全边界 | 要枚举全部配置项做校验与回写，并保管 `trusted` |
| `tui/`（终端能力库） | — | 见下 |

**做成插件**（三条同时满足：接入进程外能力或数据源 / 可选且禁用后产品完整 / 宿主只定义 seam 不关心实现）：

| 插件 | 进程外来源 | 禁用后 |
|---|---|---|
| `tools-plugin`（grep / find / ls / powershell） | 外部二进制 `rg`/`fd`/另一个 shell | `bash` 可近似，产品完整 |
| `session-plugin`（JSONL 存储 + 锁 + 导出） | 文件系统 | 内存会话仍可用 |
| `sandbox-plugin`（OS 后端 seatbelt / bubblewrap） | 操作系统机制 | `sandbox = "off"` 仍可用 |
| `mcp-plugin`（`[mcp_servers.*]`） | 外部 MCP server | 一切照常——**最标准的插件** |
| `tui-plugin`（交互式产品界面） | 终端设备 | 非交互模式完整可用 |

**`tui/` 为什么在宿主**：插件判据之一是"宿主只定义 seam、不关心其实现"，即**存在另一种实现**。终端渲染没有替代品。`tui/` 是产品赖以构建的基础设施，`tui-plugin` 才接入可选的交互形态。

**核心工具不可遮蔽**：插件注册与核心工具同名的工具时直接拒绝并报诊断。

**组合根**：`src/plugins/registry.ts` 是**唯一**导入具体插件的文件；`src/cli/bootstrap.ts` 只从插件层取清单并驱动生命周期。依赖方向严格单向：`src/plugins/** → 宿主契约`，反向不存在。

## 四、接缝与设计模式

有状态组件用类、契约用接口、纯函数用函数。

| 接缝 | 文件 | 模式 |
|---|---|---|
| `LlmClient` 接口 + 两个适配器 | `llm/client.ts`、`llm/adapters/` | 策略 |
| 按 `models.json` 的 `api` 字段构造客户端 | `llm/registry.ts` | 工厂 + 注册表 |
| `ToolRegistry`（注册、激活、校验、唯一管线） | `tools/registry.ts` | 注册表 |
| `SessionStore` 接口 + JSONL 实现 | `session/port.ts`、`session-plugin/` | 策略 |
| `SandboxBackend` 接口 + 各 OS 实现 | `sandbox/backend.ts`、`sandbox-plugin/` | 策略 |
| `PermissionPolicy`：拒绝规则 → 只读 → 写类 → 审查器 | `permission/policy.ts` | 责任链 |
| `PluginHost` + `PluginRegistry` | `plugins/host.ts`、`plugins/registry.ts` | 组合根 + 工厂 |

**`LlmClient`**：`stream(request): LlmStream`，绝不抛异常——错误编码进流。事件只发增量：`start` / `text_delta` / `reasoning_delta` / `tool_call_start|delta|end` / `usage` / `error`。**两个等级类型必须分开**：配置取值含 `off`，请求层的 effort 不含 `off`，driver 把 `off` 转成"不发 effort 参数"。模型可声明 `thinkingLevelMap` 把等级映射到 provider 原生值。重试由 `llm/retry.ts` 按 `max_retries` 负责，是宿主策略而非适配器职责。

**工具**：`ToolDefinition` = `name` / `description` / `parameters`（自写 JSON Schema 子集）/ `annotations`（只读、破坏性、开放世界）/ `prepareArguments?` / `execute(ctx)`。`ToolContext` 提供 `signal`、`onUpdate`、`workspace`、`sandbox`、`session`。核心工具与插件工具**只走注册表这一条管线**。`spill_threshold`：结果超限落盘，上下文只留预览，`0` 关闭。

**会话**：`SessionPort` 暴露追加、原始条目、当前分支条目、模型上下文投影、叶子导航、用量统计。条目类型：会话头 / 消息 / 模型变更 / 等级变更 / 压缩 / 自定义（不进上下文）/ 标签。树靠 `id` / `parentId`——**从第一天就做树**。

**沙箱**：`off | workspace | read-only`。**fail-closed**：模式非 `off` 但后端不可用（Windows 无 seatbelt/bubblewrap）时拒绝执行写操作并明确报错，**绝不静默降级**。

**权限**：`ask | auto | yolo`。`ask` 走界面确认；`auto` 由 `review_model`（省略用主模型）作为审查器判定并记录理由；`yolo` 放行。**沙箱与权限都不依赖任何工具被替换**——`bash` 通过宿主提供的沙箱接缝执行，插件只提供后端。

**TOML 层必须无损**：`[plugins] trusted` 由 `--trust` 与信任页回写，`[ui] notify` 由 `/notify` 回写。所以需要保留注释与格式的解析与定点回写；主流 TOML 库不保留注释，这一层自研是必需。实现上保存原文与节点区间，回写只替换目标键的值区间。

## 五、工程约定

- package.json：`@reins/cli`、`bin.reins`、`"type": "module"`、`engines.node >= 22.18`，scripts 仅 `typecheck`（`tsc --noEmit`）与 `test`（`node --test`）。
- tsconfig：`strict` + `erasableSyntaxOnly` + `NodeNext` + `allowImportingTsExtensions` + `verbatimModuleSyntax` + `noEmit`。
- 命名：文件目录 kebab-case；插件目录 `<能力>-plugin` 且插件标识与目录名一致；测试文件 `<被测模块>.test.ts`；类型接口类 PascalCase；接口不加 `I` 前缀；缩写小写连写（`llm`、`api`、`json` → `LlmClient`、`parseJson`）。
- 外部输入先 `unknown` 再收窄；禁 `any`；导出函数写返回类型。
- 依赖最小：手写参数解析、TOML 无损解析、JSON Schema 子集、SSE 解析、ANSI 宽度与折行。界面阶段若需要 markdown，会单独说明理由。
- 单测：`tests/` 与 `src/` 一一镜像；LLM 用脚本化假适配器驱动，不联网、不用真 key；SSE 解析用录制夹具；差分渲染断言实际发出的转义序列；TOML 用官方 toml-test 夹具（除日期时间）加自造的注释回写用例。

## 六、分阶段

每阶段都留下 typecheck 与 test 全绿、且能实际运行的东西。提交按 AGENTS.md 第七节规范，中文描述。

**P0 骨架 + 配置层** — package.json / tsconfig / `tests/` 镜像骨架 / 无损 TOML 解析与回写 / 两个配置文件加载与严格校验 / `reins config check`。
验收：能校验两个配置文件并打印解析结果；非法配置按 `行:列` 报错；定点回写在保留全部注释与格式的前提下生效。

**P1 可运行垂直切片** — `llm/` 接缝 + 两个适配器（手写 fetch + SSE）+ `max_retries` 重试 + `agent/driver.ts` + `tools/` 契约与管线 + 四个核心工具 + `spill_threshold` 落盘 + `session/port.ts` + `session-plugin` + `plugins/host.ts` 与组合根 + `tools-plugin` + `print-mode.ts`。
验收：`reins -p "读一下 README 然后加一行注释"` 用 `models.json` 里配的任意端点跑通全链路；会话落盘且**重放能还原出一致的模型上下文**；插件注册同名核心工具被拒并给出诊断。

**P2 权限与沙箱** — `permission/` 责任链（含 `auto` 审查器）+ `sandbox/policy.ts` + `sandbox-plugin` 后端 + 界面确认接线 + `--trust`。
验收：`ask` 弹批准；`auto` 由审查模型判定并留理由；`yolo` 放行；`sandbox = "workspace"` 下越界写被拒；Windows 上非 `off` 模式**明确报错拒绝而非降级**；插件注册的权限规则无法产生"放行"。

**P3 交互式界面** — `tui/` 五块 + `tui-plugin`：transcript 渲染、斜杠命令、对话框、`/notify` 与信任页回写。
验收：全屏交互流式输出不闪烁；中文与 emoji 宽度正确；窗口缩放不破版；回写后配置文件注释完好。

**P4 会话树与压缩** — 树导航、压缩（`compact_model`）、续聊与分叉、导出、用量统计。
验收：长会话压缩后能继续；被压缩掉的历史仍计入用量；分叉出的新会话带父会话链。

**P5 子代理** — 按 `max_turns` 生成子代理（子代理默认 20 步，根会话不封顶）。
验收：子代理到达步数上限后停止并向上汇报；根会话不受该上限约束。

**P6 MCP 插件** — `[mcp_servers.*]` 的 stdio 与 http（含 `type = "sse"`）；启动时后台连接、连不上进 `/mcps` 报错清单且不挡启动；控制请求固定 15 秒、`tools/call` 用 `call_timeout_ms`；`disabled = true` 不连接。
验收：**MCP 工具与核心工具在权限与沙箱上受完全相同的约束**——这条是插件体系正确性的判据。

**P7 外部插件** — 插件发现与模块加载、`/reload` 热重载、插件间只能经宿主服务通信。
验收：外部 `.ts` 插件注册工具与斜杠命令，不重新编译即生效；重载后旧上下文被判定失效。

## 七、不做

- 不做模型目录：无内置模型表、无联网抓取、无生成脚本。
- 不引参考项目里的任何包或概念（其插件运行时、持久会话框架、远程执行环境、遥测契约）。

- 不预留任何当前用不到的开关、分支与抽象。

## 九、风险

- **规模**：P3（界面）与 P4（会话树与压缩）是两个大台阶；P0–P2 可控。每阶段结束都给可运行产物。
- **「历史即状态」**最容易做错：提示词与工具声明以会话条目增量形式存在，每请求靠重放推导，绝不重算（重算会破坏压缩检查点）。P1 用「重放还原出一致的模型上下文」钉住它。
- **`context_window` 缺失**：`models.json` 未声明且 `config.toml` 未兜底时压缩阈值无法计算，按规范明确报错并提示补配置，不猜默认值。用量与成本同理——缺 `cost` 只报 token 不报金额，不显示 0。
- **Windows 沙箱**：seatbelt 仅 macOS、bubblewrap 仅 Linux，Windows 上 `sandbox` 非 `off` 会在启动时明确拒绝。
- **插件是进程内的**：能读文件、看会话、发网络请求。结构性约束是：不给模型层权限、不给放行能力、核心工具不可遮蔽、所有工具走同一管线、三项安全机制的任何异常一律阻断启动。真正的隔离靠容器化。
- **无损 TOML 解析**是唯一技术难点（回写需求使它成为必需），用官方 toml-test 夹具加自造的注释与格式回写用例兜底。

开工顺序：P0 先落 package.json / tsconfig / `tests/` 镜像骨架与无损 TOML 层，再进 P1 打通全链路。
