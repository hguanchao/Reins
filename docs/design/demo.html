REINS DESKTOP / VISUAL SYSTEM REVIEW

把控制室收进一张
排版精确的校样纸

Reins 是一个在终端里替你干活的编码智能体。界面的核心任务只有三件：让人看清 agent 正在做什么、 随时知道该自己做什么、永远不会误触危险操作。这套方案把这三件事全部压进一个纯黑白系统里—— 不靠颜色，靠明度、线宽、纹理与字形建立层级。

COLOR
界面零彩色。中性灰阶 + 纯黑强调；diff 的红绿是唯一例外。
TYPE
系统字体栈。个性放在字距与等宽刻字上。
STRUCTURE
细线分区。不用卡片堆叠，用规则线。
SIGNAL
危险靠反白。黑底白字比任何红色都响。

01四条设计判断

01会话是文档，不是聊天

去掉居中圆钮。提问是一张浅底卡，回答按正文排版，工具调用折成可展开的单行卡。一整段会话读起来像一份排版良好的工作记录，但每个控件都与主流 agent 界面同构。

02状态必须有形状

没有颜色，状态就不能只靠色相。运行=旋转 loader、完成=弱化对勾、中断=禁止圆、待确认=感叹圆。图标与明度本身就能区分，也让色觉障碍者同样可读。

03危险操作整块反白

在白纸系统里，一整块纯黑是视觉上最响的元素。破坏性操作请确认时把整张卡片倒过来，这个信号无法被忽略，也不需要任何颜色。

04线宽即层级

0.5px 分隔、1px 结构、2px 强调、整块填充即最高优先级。层级只由线宽决定，界面里不再出现投影堆叠与多层浮起。

02配色：一条中性色阶

没有品牌色，因为强调色就是墨本身。深浅两套主题共用同一组语义名，只替换明度值——组件不感知明暗，只感知层级。唯一例外是 diff 的增删行：沿用代码审阅的通用红绿，那是内容语义，不是界面信号。

03字体：九级阶梯，两种语气

离线工具不该依赖网络字体，所以坚持系统字体栈。个性不放在字体选择上，放在处理上：标题收紧字距，小标签用等宽字体拉开字距，形成仪表刻字感。

04没有颜色，状态怎么读

每个状态同时由四个通道编码，任一通道单独失效仍可辨识。这是纯黑白方案能成立的前提。

状态图标纹理 / 明度文案与位置
运行中 旋转 loader 实心墨 工具卡读数前旋转 loader；输入卡发送钮变为实心方块「停止」
待确认 感叹圆 实心墨 + 整卡 1px 描边 + 投影 卡片标题「需要确认」；快捷键 1 / 2 / 3 直接作答（高危卡除外，仅点击）
已完成 对勾 最弱明度 侧栏不显示时间，悬停才出现操作
已中断 禁止圆 次级明度 工具卡标注「已中断」；破坏性确认另走反白闸门
空闲 弱化圆点 最低对比 不写「已完成」，留白本身表示无事发生

05保留什么，改什么

现有实现的功能边界一个不删。改的是层级表达方式，不是能力集合。

完整保留

  • 三栏可拖拽框架 — 侧栏 / 主列 / 右面板，含全屏面板
  • 会话树 — 工作区分组、置顶、批量归档删除、重命名
  • 输入卡全部控件 — 附件菜单、Plan、审批方式、思考等级、模型、停止
  • 三项仪表 — 活动统计、用量、上下文占用
  • 右面板六类页签 — 文件 / Git / 技能 / 插件 / 浏览器 / 终端
  • 设置八分区 — 常规、外观、模型、个性化、扩展、统计、归档、关于
  • 双主题 + 字号缩放 — 跟随系统 / 明 / 暗
  • 键盘路径 — 命令面板、Esc 停止、审批 1/2/3

本次改动

  • 去掉彩色语义 — success / warning / destructive 全部收敛为中性与反白
  • 会话流对齐主流 — 提问浅底卡、可折叠工具卡、上下文圆环进输入卡
  • 去掉气泡与浮起主列 — 三栏齐平，用细线分区
  • 圆角收紧 — 28px 面板圆角改为 3–10px，桌面工具应有的硬边
  • 发送钮改方形 — 去掉圆形悬浮钮的通用感
  • 危险闸门反白 — 唯一的"响"留给真正需要停手的地方

02为什么不是红色

信号彩色方案本方案
注意力强度高，但会疲劳极高。整屏黑白里唯一的实心块，比彩色更难无视
色觉障碍红绿色弱完全失效无影响，与色觉无关
语义专一性红色同时表示错误、删除、超时…整卡反白只用在一处，语义不稀释
明暗主题两套红色需各自调校对比度同一套规则，深色下自然反转
可逆性区分都靠同一红色实线描边=可逆，反白=不可逆，虚线=越界

03键盘路径

常规与虚线卡出现时自动聚焦，1 2 3 直接作答，选项数量随卡片内容动态变化——只有两个选项时，3 永远是拒绝，位置从不移动。这保证了肌肉记忆不会在紧急时失效。

高危卡是唯一的例外：不接受任何数字键，只接受逐个点击。反射性的连按，不能成为放行不可逆操作的通道。

焦点环为 2px 实心墨色外描边，偏移 2px，永远可见；不使用仅靠颜色的焦点提示。

诊断信息
导出运行环境、扩展清单与最近日志，便于排查问题。

八页共用一套骨架

  • 标题即分隔 — 每页都是「等宽小标 + 27px 标题 + 一句说明 + 2px 墨线」，不再画卡片外框。
  • 行式卡片承载设置项 — 标题与一句说明在左，状态 / 开关 / 按钮统一靠右，扫读路径固定。
  • 控件按语义选型 — 互斥且需比较用并排选择卡（审批方式）；少量短选项用分段（通知、思考强度）；真值用开关。
  • 即时生效，没有页脚保存 — 只有编辑文本的「个性化」保留取消 / 保存，因为它有草稿态。
  • 导航常驻不折叠 — 五组用留白分组，小号大写等宽标题，不加分隔线。

各页的关键判断

  • 模型页保持主从 — 左 178px 提供方、右凭据与模型；不按提供方各开一页，换供应商是一等动作。
  • 扩展按类型分组 — 技能 / MCP / 插件的心智不同，页签只做过滤，清单仍分组并带数量。
  • 统计先给构成再给数字 — 单看总量判断不了钱花在哪，先画输入 / 缓存 / 输出的比例条。
  • 归档只给列表 — 低频清理动作，不配筛选器；恢复与永久删除并排，危险项用文字色区分。
  • 关于页只读 — 版本、配置路径与运行方式，唯一可操作的是检查更新与导出诊断包。

05失败与边界

明确拒绝，不静默兜底

  • 连接断开 — 顶部出现一条 2px 高的实心条，文案说明"已断开，正在重连"，恢复后自动消失。
  • 工具执行失败 — 该行改为斜纹底，行尾显示错误摘要；不影响后续步骤继续。
  • 审批超时 — 卡片保留但按钮变禁用，提示"该请求已失效，重新发起"。不自动允许。
  • 上下文溢出 — 输入卡上方出现虚线提示条，给出"压缩上下文"按钮，不擅自截断。

危险操作的硬约束

  • 不可逆操作必须列出目标 — 只写"删除文件"不算说明，必须给出路径与数量。
  • 不提供"永不询问"快捷 — 高风险类目下，最多只能"总是允许"当前这一个工具。
  • 反白卡不接受双击确认，也不接受数字键 — 必须逐个点击按钮，反射性连按无法放行不可逆操作。
  • 焦点不可默认落在允许上 — 卡片获得焦点时，默认焦点是卡片本身而非任何按钮。
